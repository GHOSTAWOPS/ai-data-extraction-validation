### 2.1.2 数据流向

```
用户输入(DOCX+Excel)
    ↓
文档解析(unstructured) → JSON缓存
    ↓
文本分块(RecursiveCharacterTextSplitter)
    ↓
Embedding(BGE-M3) → 向量(768维)
    ↓
ChromaDB存储
    ↓
【循环处理每个关键词】
    ↓
混合检索(向量+BM25) → top-120候选
    ↓
Rerank精排(微调BGE-reranker) → top-5/60
    ↓
Prompt构造(关键词+检索上下文)
    ↓
LLM推理(通义千问72B) → 结构化答案
    ↓
可选RAGAS评估 → 质量打分
    ↓
结果填充到Excel → 输出文件
```

## 2.3 分层架构设计

### 2.3.1 展示层（Presentation Layer）

**职责**：用户交互界面

**组件**：
- Gradio Web UI
- 4个功能页面：预处理、提取、复核、模板管理
- 自定义CSS样式

**特点**：
- 低代码：Gradio声明式UI，无需前端开发
- 实时反馈：进度条、状态更新
- 文件管理：上传、下载、预览

### 2.3.2 业务逻辑层（Business Logic Layer）

**职责**：核心业务流程编排

**主要文件**：main.py

**核心函数**：
- `preprocess_file()` - 文档预处理
- `process_extract()` - 数据提取
- `process_check()` - 数据复核
- 模板管理函数群

**特点**：
- 流程控制：Generator模式实时yield进度
- 异常处理：统一错误捕获和日志记录
- 并发控制：concurrency_limit限制

### 2.3.3 数据处理层（Data Processing Layer）

**职责**：文档解析与转换

**主要模块**：
- data_processor_new_zbb_structured.py
- utils/xlsx_utils.py
- utils/docx_utils.py
- utils/utils.py

**核心能力**：
- 文档解析：unstructured提取结构化数据
- 分块处理：RecursiveCharacterTextSplitter
- 格式转换：JSON缓存、Markdown转换
- 文件操作：Excel读写、DOCX标注

### 2.3.4 AI模型层（AI Model Layer）

**职责**：智能推理与检索

**子层划分**：

**1. 检索子层**
- Embedding：BGE-M3向量化
- 向量数据库：ChromaDB存储与检索
- 混合检索：向量+BM25融合

**2. 排序子层**
- Rerank模型：精排top-K
- 分数归一化

**3. 生成子层**
- LLM推理：通义千问72B
- Prompt工程：动态模板构造
- 输出解析：结构化答案提取

**主要文件**：
- models/extract_model.py - 提取核心
- models/new_check_model.py - 复核核心
- models/llm_model.py - LLM加载器
- models/embedding_model.py - Embedding加载器
- models/new_rerank_model.py - Rerank实现
- models/vectorstore.py - 向量库操作

### 2.3.5 辅助模块层（Helper Module Layer）

**职责**：增强功能与工具

**模块**：
- QueryRewrite：查询改写
- RAGAS：答案质量评估
- Structured：数据结构化
- prompt_engineering.py：Prompt模板库

### 2.3.6 存储层（Storage Layer）

**职责**：数据持久化

**存储类型**：

1. **文件存储**：
   - 输出文件：output_excels/
   - 模板文件：extract_templates/
   - 日志文件：logs/

2. **缓存存储**：
   - JSON缓存：output_jsons/
   - 表格信息：table_jsons/
   - Rerank结果：rerank_jsons/

3. **临时存储**：
   - 向量数据库：ChromaDB临时集合
   - 上传文件：Gradio临时目录
   - 下载文件：downloads/

## 2.4 模块间通信

### 2.4.1 同步调用

```python
# main.py → data_processor
elements = zbb_structure_parser_process_docx(doc_file_path)

# main.py → models/extract_model
for ans in call_extract_model(tbl_info, retriever, ...):
    yield ans

# extract_model → llm_model
model = get_llm_model(model_type="ollama")
```

# Gradio事件驱动

# 首次处理生成JSON
json_file = f"{name_word}_table_info.json"

## 2.5 技术选型理由

| 技术 | 为什么选它？ | 替代方案 |
|------|-------------|----------|
| **Gradio** | 快速原型，零前端开发 | Streamlit、Dash |
| **LangChain** | RAG标准框架，生态完善 | LlamaIndex、Haystack |
| **BGE-M3** | 中文优秀，多模式检索 | text-embedding-3、m3e |
| **ChromaDB** | 轻量级，无需独立服务 | Milvus、Weaviate |
| **通义千问72B** | 中文能力强，成本可控 | GPT-4、Claude |
| **unstructured** | 开源，支持格式广 | PyMuPDF、Docling |
