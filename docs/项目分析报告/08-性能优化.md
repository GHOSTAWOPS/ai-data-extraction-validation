# 第八章：性能优化与特点

## 8.1 性能优化点

### 8.1.1 JSON缓存机制

**优化目标**：避免重复解析文档

**实现**（main.py:343-356）：
```python
# 首次处理：解析文档并生成JSON
if json_file is None:
    elements = zbb_structure_parser_process_docx(doc_file_path)
    save_json(json_file, elements)  # 耗时5-30秒
    
# 后续处理：直接读取JSON
else:
    elements = load_json(json_file)  # 耗时<1秒
```

**效果**：
- 首次处理：5-30秒
- 后续复用：< 1秒（提速30-50倍）

### 8.1.4 批量向量化

**优化目标**：减少GPU调用次数

**实现**（models/embedding_model.py）：
```python
def embed_documents(self, texts):
    # 批量编码（而非逐个）
    embeddings = self.model.encode(
        texts,
        batch_size=32,  # 批处理
        show_progress_bar=True
    )
    return embeddings.tolist()
```

**效果**：
- 512个chunk，批量编码约30秒
- 逐个编码需约5分钟（提速10倍）

### 8.1.5 异步文件清理

**优化目标**：后台清理，不阻塞主流程

**实现**（utils/file_cleanup.py）：
```python
import threading

def continuous_cleanup():
    while True:
        time.sleep(CONFIG.interval_hours * 3600)  # 每2小时
        cleanup_old_files(
            folders=["output_excels", "output_jsons"],
            max_age_hours=CONFIG.max_age_hours  # 保留7天
        )

# 启动后台线程
cleanup_thread = threading.Thread(
    target=continuous_cleanup,
    daemon=True
)
cleanup_thread.start()
```

## 8.2 系统特点

**多层质量保障**：

#### 2. 可追溯性

### 8.2.2 局限性

#### 1. 文档格式限制
**支持情况**：
| 格式 | 支持程度 | 说明 |
|------|---------|------|
| DOCX | ✅ 完整 | 核心支持格式 |
| DOC | ⚠️ 有限 | 需转换为DOCX |
| PDF | ⚠️ 有限 | 文本PDF可解析，扫描PDF需OCR |
| 图片 | ❌ 不支持 | 未集成OCR |

---

#### 2. 计算资源需求
**硬件要求**：
- GPU：推荐16GB+ VRAM
- 内存：32GB+
- 存储：模型文件约4GB

**云端部署成本**：
- AWS g4dn.xlarge：约$0.5/小时
- 阿里云ECS GPU实例：约¥3/小时

---

#### 3. 处理速度
**耗时统计**（100页文档，50个关键词）：
| 阶段 | 耗时 |
|------|------|
| 文档解析 | 10-20秒 |
| 向量化 | 20-30秒 |
| 提取查询 | 5-8分钟 |
| **总计** | **6-10分钟** |

**优化空间**：
- 批量查询：可并行处理多个关键词
- 模型量化：FP16→INT8（速度提升2倍）

---

#### 4. 长文档挑战
**问题**：
- 超过500页文档：分块数量过多（>1000）
- 检索性能下降：top-120覆盖度不足

**解决方案**：
- 文档分段：按章节拆分
- 增加检索范围：top-200
- 使用QueryRewrite扩展查询

---

#### 5. 复杂表格处理
**挑战**：
- 多级表头
- 合并单元格
- 嵌套表格

**当前表现**：
- 简单表格：准确率90%+
- 复杂表格：准确率70-80%
